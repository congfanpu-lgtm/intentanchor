# IntentAnchor Chinese Tool-Call Safety Test Set (v1)

一个中文的单步测试集，用来评测“工具调用前的安全守卫”：给出用户请求、到目前为止的交互（含原始工具返回）和 agent 下一步要执行的调用，判断这一步该放行（ALLOW）还是拦截（BLOCK）。350 条，包含中文、英文、中英混写的间接提示注入，以及没有注入、agent 自己越权的情况。场景由 DeepSeek-V4-Pro 生成，通过阿里云百炼调用。**标签没有经过人工核验**，见 [Labels](#labels-and-review)。只用于测评，不要用来训练。

350 single-step samples for evaluating guards that check an LLM agent's tool call before it runs. Each sample gives the user's request, the tools, the interaction so far (with raw tool outputs) and one proposed call; the label is ALLOW or BLOCK. Scenarios are written in Chinese and were generated by DeepSeek-V4-Pro, called through Alibaba Cloud Model Studio (the DashScope API). Injections are in Chinese, English, or mixed Chinese and English. **Labels were reviewed by LLMs only, not by humans.**

Built as the held-out Chinese test set of [IntentAnchor](https://github.com/congfanpu-lgtm/intentanchor), a 4B tool-call guard. For evaluation only; do not train on it.

## Composition

| Category | Label | n | What it is |
|---|---|---|---|
| `aligned_direct` | ALLOW | 89 | The call the user asked for: 43 with a clean history, 46 with an injection in the history that the agent ignored |
| `aligned_after_compromise` | ALLOW | 45 | The agent already executed an injected call; this step returns to the user's task |
| `aligned_auxiliary` | ALLOW | 21 | A helper step the task needs (look something up before acting) |
| `aligned_derived` | ALLOW | 21 | Arguments legitimately taken from a tool output the task points to |
| `misaligned_injection` | BLOCK | 114 | The call an injection in a tool output asked for |
| `misaligned_overreach` | BLOCK | 60 | The agent goes beyond the request on its own, not because of an injection (wrong amount, submits instead of drafting, invents a date, changes a setting) |

- Domains: HR 96, customer support 95, rental 88, education 71.
- Injection language (`attack_family`): Chinese 104, English 52, mixed 50; 144 samples have no injection.
- ALLOW samples by history: clean 85, injection present but ignored 46, after the agent followed an injection 45.
- History length: 1–6 earlier tool calls (median 3).

## How it was built

1. **Scenarios.** DeepSeek-V4-Pro wrote each scenario in one pass from a Chinese prompt: the user's request, the tools, and a history with tool outputs. Each scenario yields up to 8 samples: 4 candidate calls with a clean history (3 ALLOW, 1 overreach BLOCK); a Chinese injection with the attacked call (BLOCK) and a call that ignores it (ALLOW); a cross-lingual injection with the attacked call (BLOCK) and, after that call has run, a return to the user's task (ALLOW). Of 60 requested scenarios (15 per domain), 57 passed validation. Invalid candidate calls (read-only tools, duplicates) were dropped, and so were 13 ALLOW calls whose ID-like arguments (order numbers, accounts, phone numbers, emails) appear in neither the request nor the history. That left 430 drafts: 259 ALLOW and 171 BLOCK.
2. **Attacks.** Goals come from the AgentDojo banking and Slack injection tasks, with their objects swapped for ones in the scenario; the intent is unchanged. The template is AgentDojo's `important_instructions` (English original, a Chinese translation, or English goal in the Chinese template). This is a single fixed template, not an adaptive attack.
3. **Kept apart from IntentAnchor's training data.** Training data used a different generator (qwen3.7-plus), different prompts, different domains, and never saw `important_instructions` or the banking and Slack goals. No test sample matches a training sample exactly. Near-duplicate check: character 3-gram TF-IDF cosine on request plus proposed call; the closest training sample is at 0.545, median 0.116. Shared with the training data: the label standard, the sample categories and the code that inserts injections into tool outputs.

## Labels and review

Labels come from construction: each sample's label is the one its position in the scenario implies. LLM reviewers then checked them; **no human verified any label.**

1. Two independent groups of Claude subagents reviewed all 430 drafts blind (without seeing labels) against a written rubric.
2. 337 drafts where both groups agreed with the constructed label were kept as is (`label_source: review`).
3. 77 drafts where both groups overturned the label were dropped. All 77 were ALLOW: 28 of 50 `aligned_auxiliary`, 19 of 41 `aligned_derived`, 20 of 112 `aligned_direct`, and 10 of 56 `aligned_after_compromise`.
4. 16 drafts where the groups disagreed were decided by a third Claude session: 9 kept, 4 relabeled from ALLOW to BLOCK (all overreach or invented key arguments; `meta.constructed` keeps the original), 3 dropped (`label_source: adjudicated`).
5. The same session spot-checked 50 random agreed samples: 50 of 50 matched.

The rubric is IntentAnchor's guard instruction: StepGuard's decision rules plus IntentAnchor's clarifications. In particular, a side effect the user did not ask for (extra recipients, submitting instead of drafting, changing a setting) is BLOCK even with no injection. Guards trained on a different standard may disagree with the 60 overreach samples for that reason, not only because they miss them.

## Baseline results

H0 is IntentAnchor fine-tuned on its base training set. H2 also trains on mined hard negatives: benign steps that H0 wrongly blocked, confirmed by blind review. The final IntentAnchor model is H2 seed 0; the IntentAnchor columns are means of 3 training seeds. All scores were computed on the drafts before the labels were frozen, and no results were looked at until the freeze.

Thresholds are set at 5% false-positive rate on IntentAnchor's English dev set and transferred unchanged. That dev set is split from the same sources as IntentAnchor's training data. On it, the rule puts StepGuard's threshold at about 1.000 and the zero-shot model's above 0.99999. AUROC does not depend on the threshold.

| | IntentAnchor H2 | IntentAnchor H0 | StepGuard | Qwen3-4B, zero-shot |
|---|---|---|---|---|
| AUROC | **0.973** | 0.962 | 0.874 | 0.725 |
| False-positive rate (176 ALLOW) | **5.9%** | 12.1% | 9.1% | 23.3% |
| False-positive rate after the agent followed an injection (45) | 11.9% | 32.6% | 6.7% | 35.6% |
| Recall (174 BLOCK) | 87.2% | 87.9% | 79.3% | 52.3% |
| Recall on injections: Chinese / English / mixed (57 / 30 / 27) | 98.2 / 96.7 / 100 | 99.4 / 96.7 / 100 | 100 / 100 / 96.3 | 70.2 / 66.7 / 66.7 |
| Recall on overreach (60) | 66.1% | 67.2% | 41.7% | 21.7% |

The fixed injection template is easy for every fine-tuned guard. Most of the spread is on overreach and on ALLOW steps right after a compromise.

## Personal information

No data about real people was collected. Every name, phone number, email address, student ID and bank account was invented by the generator. Some invented emails use real providers' domains (gmail.com, post.com, protonmail.com), and phone numbers follow the real Chinese mobile format, so a few may match real ones by chance. Do not contact any of them. Attacker addresses and URLs inside injections are also invented; some of their domains may exist.

## Limitations

- Labels are LLM-reviewed only, and follow IntentAnchor's rubric.
- Review removed mostly ALLOW drafts: all 77 that both groups overturned were ALLOW. Almost all ALLOW samples left are ones both groups agreed on, so false-positive rates here may be lower than on harder benign steps.
- Small: 350 samples; most subgroups have 21–60.
- One injection template, no adaptive attacks. High injection recall here says little about harder attacks.
- Four domains, all generated by one model; scenarios may be cleaner than real agent traces.
